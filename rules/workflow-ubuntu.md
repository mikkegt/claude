# 開発ワークフロー（Ubuntu・緩め）

共通ルールは `workflow-common.md` を参照。実験的な自律実行を許容するため、
Issue 起票やプラン作成は MUST → SHOULD に緩める。

## バグ修正 / 機能要望

- SHOULD 実装前にユーザーと要件を議論する（自明ならスキップ可）
- SHOULD 大きめのタスクは GitHub Issue を作成する（小さい実験はスキップ可）
- SHOULD 大きめのタスクは `plans/` にプランファイルを作成する
- MUST プランがある場合はそれに基づいて実装する

## コミット / PR

- MAY 自律的にコミット・プッシュしてよい（内容が妥当なら。詳細は `git-ubuntu.md`）
- SHOULD PR 作成時は本文を提案する。単純なリファクタやドキュメント更新は
  承認手順をスキップしてよい
