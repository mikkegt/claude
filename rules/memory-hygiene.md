# memory に書くもの・書かないもの

memory は書いた時点のスナップショット。読む側（次のセッションの Claude）は、その記述が今も有効かを判断できない。腐る記述を書くと、古い前提のまま判断して事故になる。

しかも事故は静かに起きる。誤った memory を信じて実装し、人間が気づいて指摘するまで分からない。指摘するコストが毎回人間側にかかると、AI で効率化したはずが負担の移転になる。

## NEVER 書かない: Claude 自身の状態

- 「読了」「全文読んだ」「確認済み」「把握した」
  読んだのは記録を書いたセッションの Claude。次のセッションは読んでいない状態から始まる。「読了」と書いてあると「もう確認しなくてよい」と誤読し、参照すべき資料を飛ばす
- 「理解した」「覚えた」
  同上。セッションをまたいで引き継がれるのは memory の中身だけ

## NEVER 書かない: 検証せずに使える形の状態

- 「対応済み」「修正した」「実装した」（コードの状態を指すもの）
  コードは変わる。git log と現物を見れば分かることを memory に固定しない
- 「マージ待ち」「レビュー中」（外部システムの状態）
  数時間で変わる

## MUST 状態を書くときは、確認方法を併記する

状態を書かざるをえない場面はある（進行中の作業、待ちの理由、担当の割り当て）。そのときは、その記述が今も有効かを確かめるコマンドや手順を必ず添える。

    - この設定は誰も参照していない（確認: `grep -rn <識別子> src/`）
    - 依頼した変更はレビュー待ち（確認: `gh pr view <番号> --json state`）

読む側が 5 秒で古さを検出できる形にする。

## SHOULD 書くもの（腐りにくい）

- どこに何があるか（ファイルパス、ドキュメントの節、関数名・シンボル名）。
  行番号は書かない。ファイルが伸びると別の場所を指すようになり、しかも参照として
  成立して見えるので、ずれたことに気づけない
- なぜそう決めたか（判断の理由、却下した案とその理由）
- いつ読むか / いつ実行するか（手順、着手前のチェック項目）
- 環境差・実測値（測った環境と日付を必ず添える）
- 人が言った制約・好み（誰が、いつ言ったか）

## MUST 参照は、動かない手がかりで書く

参照は壊れてもエラーにならない。書いた時点では正しく、後からずれ、ずれた後も参照としては成立して見える。だから読む側は、開いて確かめるまで違いに気づけない。ずれ方は 2 種類ある。

位置の参照がずれる。行番号は、前に行が挿入されるだけで別の場所を指す。指した先にも何か書いてあるので、読む側は「ここに書いてあることが根拠なのだろう」と解釈してしまう。参照先が無くなって気づくのではなく、無関係な内容を根拠として受け取るのが厄介なところ。

存在の参照がずれる。「grep で見つからなかった」は、確認したコミットに無いという意味であって、実装されていないという意味ではない。別ブランチ、別の綴り、生成されるコードのどれでも同じ結果になる。「無い」と書いた memory は、後から入った実装を隠す。

書くなら、内容と一緒に動く手がかりを使う。節の見出し、関数名、型名、識別子、設定キー。読む側が自分で grep して引き直せる形にする。存在の否定を書くときは、確認したコマンドと範囲を併記して、否定の射程を限定する。

    - 呼び出し箇所は <モジュール名> の <関数名>（確認: `grep -rn <関数名> src/`）
    - <識別子> の参照は無い（確認: 2026-01-01 に `grep -rn <識別子> src/` が 0 件。生成コードは未確認）

## MUST 日付を添える

すべての記述に「いつ時点の話か」を書く。日付があれば、読む側が古さを疑える。相対表現（「先週」「最近」）は使わない。絶対日付にする。

## 実例（一般化）

あるプロジェクトで、参照すべき設計ドキュメントについて memory に「全文読了」と記録していた。次のセッションの Claude はそれを見て「確認済み」と解釈し、実装前に該当箇所を読まなかった。結果、そのドキュメントに書かれていた決定を無視した実装を出し、他メンバーが自分の実装を取り下げる形になった。

同じ資料の見落としは、その前にも起きていた。memory には「実装前に該当節を grep する」と書いてあったが、同じファイルの別の箇所に「読了」とあったため、手順のほうが打ち消された。

## 棚卸し

腐りやすい記述を定期的に洗う。

    grep -rlE "読了|確認済み|把握した|対応済み|修正済み|実装済み|マージ待ち|レビュー中" <memory ディレクトリ>

ヒットしたものは、確認方法を併記するか、事実の記述に書き換える。

行番号での参照も洗う。

    grep -rnE "\.[a-z]+:[0-9]+|[0-9]+ ?行目|:[0-9]+-[0-9]+" <memory ディレクトリ>

ヒットしたものは、節の見出しや関数名に置き換える。置き換える前に参照先を開き、書かれた当時から動いていないかを確かめる。動いていれば、参照を持つ memory の記述自体が誤っている可能性がある。
