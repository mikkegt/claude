# 開発ワークフロー

## バグ修正 / 機能要望

1. MUST ユーザーと要件を議論・明確化する
2. MUST スコープが明確になったらGitHub Issueを作成する
3. MUST リポジトリの `plans/` ディレクトリにプランファイルを作成する
4. MUST プランに基づいて実装する
5. MUST PR/MRの説明に「背景」セクション（なぜこの変更が必要か）を含める。ユーザーの生のプロンプトをそのまま転記しない（Claude Code 生成マーカーの扱いは `git-mac.md` / `git-ubuntu.md` を参照）
6. MUST AI（Claude 含む）が実装した PR は、説明の**最上位**に「Summary」節と「Items to Confirm / Review」節を置く。人間レビュワーが「何が変わったか」「何を特に見てほしいか（リスクある判断・仮定・未検証の挙動）」を最初に把握できる形にする。背景・実装詳細はその後

## コミット / PR の標準フロー

1. MUST コミット前にコミットメッセージを提案し、承認を得てからコミット & プッシュ
2. MUST プッシュ後に PR 本文を提案し、承認を得てから PR 作成（PR 作成は外部発信なので原則ユーザーが行う）

## ドキュメントのメンテナンス

- MUST 変更後にREADME.mdを確認し、正しい仕様を反映する
- MUST コマンド例、オプション、使い方の説明が正確であることを確認する
