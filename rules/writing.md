# ライティング（人間向け出力の軽い既定）

ユーザーへの回答・PR 本文・コミットメッセージ・コメント・人間向け docs に薄く効く既定。

- SHOULD bold を多用しない。強調が本当に要る箇所だけ。
  箇条書きの項目名は太字にしない（例: `**速度:** 大幅に改善` → `速度: 大幅に改善`）
- SHOULD PR 本文・コミットメッセージ・PR コメントでは、原則 bold を使わない
- SHOULD Claude が読む設定ファイル（rules/ 等）では bold は使わない（実効が無い）
- SHOULD 過剰なヘッジングを避ける。言い切れるところは言い切る
- SHOULD 「重要です」「不可欠です」等の過剰な強調を削る

## 使わない語彙

MUST 下表の語を使わない。レポート・PR 本文・報告書・MTG メモなど、人間の読み手に
届く文章が対象。会話内での使い捨てと、コード内の識別子・文字列は対象外。

| 使わない | 代替 |
|---|---|
| 本丸 / 本丸版 | 指す対象を具体名で書く |
| 宿題 | 持ち帰った項目、次回以降の検討事項 |
| 素直 | 単純 |
| 推し | 推奨 |
| 踏襲 | 引き継いでいる、そのまま使っている |
| 模倣 / 真似ている | 同じ形にしている、寄せている |
| 初出 | 最初に出てきた、初めて書かれた |
| 観察（体言止め） | 見えた、確認した |
| 留意 | 気をつける |
| 副次的 | あわせて、もう一つの |
| 本検証 | 今回の検証 |
| 概ね | ほとんど |
| 合意する | 決める、まとまる、すり合わせる |
| 浮き彫りにする | 分かった、見えた |
| 示唆しています | と読める、かもしれない |

これらは実際に指摘を受けた語だけを載せている。新たに指摘されたら、この表に足す。

チェック用 grep:

    grep -nE "本丸|宿題|素直|推し|踏襲|模倣|真似|初出|留意|副次的|本検証|概ね|合意|浮き彫り|示唆"

## 主語と、指す対象

文書は単独で読まれる。読み手はその会話にいなかった人か、時間が経ったユーザー本人か、
新しいセッションの Claude。書いた本人だけが参照を解決できる状態にしない。

- MUST 主語を書く。「〜されている」「〜が判明した」で終えず、誰が何をしたのかを書く。
  自分（Claude）とユーザーがやったことを、第三者がやったように書かない
- MUST 指示語（この / その / あれ / 前の / 先ほど / 上記 / 例の）は、指す対象が同じ
  文書内にあるときだけ使う。会話の文脈でしか解決しないものは具体名に置き換える
- MUST 独自のラベル・略語（章番号、案 A、検証 3、タスク記号）は、その文書で最初に
  使うときに何を指すか書く。定義せずに使わない
- MUST 数字を単独で置かない。「1/4 → 4/4」のような値は、何の母数で何を数えたかを添える
- SHOULD 抽象的な言い換えで済ませない。「対応した」「改善した」ではなく、何をどう
  変えたのかを書く

書き終えたら指示語を洗い出し、それぞれ文書内で解決するか確認する:

    grep -nE "この|その|あれ|前の|先ほど|上記|後述|例の|同様に"

語彙表と違い、ヒットしたものが全部悪いわけではない。読んで判定する。
